Goals

  • One place a hiring manager can see what I've actually done, not just what I've studied.
  • Readable on a phone in under a minute; deep enough to read for ten.
  • No frameworks or build step, so I understand every line.

Version 1

The first build was a dark, SOC-themed site with an animated "terminal," particle background, and a page for each lab. It worked, but each page carried its own copy of the styles, a few sections were still placeholders, and the lab pages read more like assignment outlines than write-ups.

Version 2 redesign

  • One design system. All pages share one stylesheet built on color and spacing tokens. No more per-page <style> blocks.
  • Real content only. Removed placeholder sections and simulated dashboard data. Everything on the page is something I did.
  • Lab template. Every lab follows the same structure: scenario, walkthrough with the actual commands and queries, a reference table, and takeaways, with ATT&CK mapping where it applies.
  • Accessibility. Skip link, semantic landmarks, alt text on every screenshot, visible focus states, and reduced-motion support.
  • Printable resume. The resume page has print styles, so the PDF is generated from the same source as the web version.

Security choices

  • Removed third-party JavaScript libraries loaded from CDNs. The site's only script is my own (~100 lines).
  • External links use rel="noopener".
  • Static hosting means no server, database, or forms to attack.

What I learned

  • CSS grid and flexbox for responsive layouts, and design tokens for consistency.
  • Git workflow: small commits, readable history, GitHub Pages deployment.
  • Writing for the reader: explaining technical work so it's useful to someone else.
