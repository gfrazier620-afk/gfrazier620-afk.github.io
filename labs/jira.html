Tracking Security Findings in Jira

Findings that aren't tracked don't get fixed. I set up a Jira project to manage the results of my vulnerability scanning lab from discovery to verified fix.

  • Jira
  • JQL
  • Kanban
  • Remediation
Environment
Jira Cloud (free)
Tools
Kanban board, JQL, Dashboards
Focus
Workflow & remediation tracking

On this page

  1. Walkthrough
  2. Key takeaways

Walkthrough

  1. Create the project

    A Kanban project SEC with the workflow To Do → In Progress → In Review (rescan) → Done.

  2. Log each finding as an issue

    One issue per finding from the vulnerability lab, with the affected asset, CVE, severity, evidence, and the fix. Label vulnerability.

  3. Set due dates by severity

    Remediation SLAs: Critical 7 days, High 30, Medium 90. The due date makes overdue work visible.

  4. Query with JQL
    project = SEC AND labels = vulnerability
  AND priority in (Highest, High)
  AND statusCategory != Done
ORDER BY duedate ASC
  5. Build a dashboard

    Gadgets for open findings by priority, overdue issues (duedate < now() AND resolution = Unresolved), and created-vs-resolved over time.

Key takeaways

  • The In Review column is the rescan step. Nothing moves to Done on someone's word alone.
  • JQL makes a backlog searchable, and searchable is reportable.
  • Clear tickets and clear status reporting are a big part of the analyst job.
