Linux Command Line for Investigations

Most servers run Linux. I practiced the commands an analyst uses to answer the questions that come up on a Linux host: who logged in, who tried to, what's running, and what changed.

Walkthrough

  1. Top IPs failing SSH logins

    A one-line pipeline that turns auth.log into a ranked list of attackers.

    grep "Failed password" /var/log/auth.log \
  | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr | head
  2. Did any of them get in?
    grep "Accepted" /var/log/auth.log
last -a | head
sudo lastb | head          # failed logins
  3. Same data through systemd
    journalctl -u ssh --since "1 hour ago"
  4. Users and privileges

    Look for unexpected accounts with a login shell, or UID 0.

    awk -F: '$3 == 0 || $7 ~ /bash|sh$/ {print $1, $3, $7}' /etc/passwd
sudo -l
getent group sudo
  5. Processes and listeners
    ps aux --sort=-%cpu | head
ss -tulpn
  6. Hunt for persistence and tampering
    crontab -l; ls -la /etc/cron.*
find / -perm -4000 -type f 2>/dev/null     # SUID binaries
find /etc -mtime -1 -type f                # changed in last 24h

Key takeaways

  • grep | awk | sort | uniq -c is the analyst's Swiss army knife for any text log.
  • An unexpected UID 0 account or a new SUID binary is a critical finding.
  • Cron is the Linux equivalent of a Windows scheduled task, and an equally common persistence spot.
