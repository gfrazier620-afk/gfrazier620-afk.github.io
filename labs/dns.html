DNS Investigation

Nearly every attack touches DNS: phishing domains, malware callbacks, data exfiltration. I practiced resolving records by hand and learned what malicious DNS looks like.

Walkthrough

  1. Query common record types
    nslookup example.com
nslookup -type=mx example.com
dig example.com A +short
dig example.com TXT
dig -x 8.8.8.8          # reverse lookup
  2. Follow resolution end to end

    +trace walks from the root servers to the TLD to the authoritative server, the whole delegation chain.

    dig example.com +trace
  3. Inspect and clear the local cache

    The cache shows what a host has recently looked up, which is useful during an investigation.

    ipconfig /displaydns
ipconfig /flushdns
  4. Check the hosts file

    Malware sometimes edits it to redirect or block security sites.

    type C:\Windows\System32\drivers\etc\hosts
  5. Look at DNS on the wire

    In Wireshark: dns, and dns.flags.rcode == 3 for failed lookups.

Record types

RecordPurpose
A / AAAAName → IPv4 / IPv6
CNAMEAlias to another name
MXMail servers for the domain
TXTSPF, DKIM, verification (also abused for tunneling)
NSAuthoritative name servers
PTRIP → name (reverse)

What suspicious DNS looks like

PatternPossible cause
Long random subdomains (a9x3kq...example.net)DNS tunneling or exfiltration
Bursts of NXDOMAIN to random-looking domainsDomain generation algorithm (DGA) malware
High volume of TXT queries from one hostTunneling / C2
Lookalike domains (rnicrosoft.com)Phishing / typosquatting
Newly registered domainsPhishing infrastructure

Key takeaways

  • DNS logs are one of the cheapest, highest-value data sources a SOC can collect.
  • One infected host often shows up in DNS before it shows up anywhere else.
