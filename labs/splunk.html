Splunk Search Fundamentals

I loaded web server access logs into Splunk and used SPL to get from raw events to an answer: which client is scanning the site, and how to watch for it on a dashboard.

Objective

Get comfortable with the core SPL workflow every SOC uses: filter → transform → visualize. Then use it to answer a real question: is anyone probing this web server?

Search hygiene: always narrow by index, sourcetype, and time range first. That's the difference between a search that returns in seconds and one that scans everything.

Walkthrough

  1. Ingest the data

    Settings → Add Data → Upload, set sourcetype to access_combined so Splunk extracts fields like clientip, status, and uri automatically.

  2. Get a feel for the traffic

    Status code breakdown shows the error rate at a glance.

    index=main sourcetype=access_combined
| stats count BY status
| sort - count
  3. Find the noisiest clients
    index=main sourcetype=access_combined
| top limit=10 clientip
  4. Hunt for scanning behavior

    A scanner shows up as one IP producing lots of 404s across many different paths.

    index=main sourcetype=access_combined status=404
| stats count AS errors dc(uri) AS unique_paths BY clientip
| where unique_paths > 50
| sort - errors
  5. Pull the requested paths

    Requests like /admin, /.env, /wp-login.php, or /phpmyadmin point to automated reconnaissance rather than a broken link.

    index=main sourcetype=access_combined clientip="198.51.100.23"
| table _time method uri status useragent
  6. Visualize and save to a dashboard

    A timechart of errors split by status, saved with Save As → Dashboard Panel.

    index=main sourcetype=access_combined status>=400
| timechart span=15m count BY status

SPL commands I used

CommandWhat it does
statsAggregate: count, dc (distinct count), values, avg, by a field
top / rareMost and least common values of a field
whereFilter on calculated results (after stats)
timechartTime-series aggregation for charts
tableChoose and order output columns
sort -Descending sort

Key takeaways

  • dc(uri) is what separates a scanner from a user with one broken bookmark.
  • The user agent often gives tooling away (sqlmap, Nikto, python-requests).
  • A dashboard panel turns a one-time hunt into ongoing visibility.
