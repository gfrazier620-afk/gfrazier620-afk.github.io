Walkthrough

  1. Identify the host's addressing

    IP, subnet mask, gateway, and DNS servers. For example, 192.168.1.0/24 has 254 usable hosts, .1 through .254.

    ipconfig /all          # Windows
ip addr && ip route     # Linux
  2. Test reachability and path
    ping 8.8.8.8
tracert 8.8.8.8        # Windows
traceroute 8.8.8.8     # Linux
  3. List listening ports and connections

    The -o / -p flags show the owning process, which is the key to security triage.

    netstat -ano           # Windows
ss -tulpn              # Linux
  4. Tie a port to a process

    An unexpected listener gets traced to its executable.

    Get-Process -Id 4312 | Select-Object Name, Path
  5. Watch the handshake

    Confirmed the SYN → SYN/ACK → ACK setup and FIN/ACK teardown in Wireshark (see the Wireshark lab).

Ports worth memorizing

80 / 443HTTP / HTTPSMost web attacks and C2
445SMBLateral movement, ransomware spread
3389RDPTop initial-access vector when exposed

Key takeaways

  • A port number alone isn't proof of anything. Confirm which process owns it.
  • Knowing what's normal on a host is what makes the abnormal stand out.
