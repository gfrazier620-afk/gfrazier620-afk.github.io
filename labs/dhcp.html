DHCP & Rogue Server Detection

DHCP hands every device its IP, gateway, and DNS server, so a rogue DHCP server can quietly reroute an entire network. I captured the normal exchange and learned how to spot an impostor.

  • DHCP

Environment
Lab VMs on a shared virtual network
Tools
ipconfig, Wireshark
Focus
DORA, options, rogue detection

Walkthrough

  1. Trigger a fresh lease

    Release and renew while capturing in Wireshark.

    ipconfig /release
ipconfig /renew
  2. Watch DORA

    Discover → Offer → Request → Ack, using the filter:

    dhcp
  3. Decode the options

    Expand the Offer packet and read what the server is handing out.

    OptionMeaning
    53Message type (1 Discover, 2 Offer, 3 Request, 5 Ack)
    54Server identifier: who is offering
    3Router (default gateway)
    6DNS servers
    51Lease time
  4. Detect a rogue server

    List every Offer and check the server identifier. More than one server answering, or a gateway or DNS server you don't recognize, is the red flag.

    dhcp.option.dhcp == 2
  5. Recognize a failed lease

    A 169.254.x.x (APIPA) address means the client got no answer at all. That can be an outage, or a DHCP starvation attack.

Key takeaways

  • A rogue DHCP server is a man-in-the-middle attack: whoever controls the gateway and DNS controls the traffic.
  • On real networks, DHCP snooping on switches blocks Offers from untrusted ports.
  • Option 54 is the first thing to check when addressing looks wrong.
