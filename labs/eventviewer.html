Investigating Logons with Windows Event Viewer

Before logs ever reach a SIEM, they live in Event Viewer. In this lab I learned to read Windows authentication events at the source: what each field means and how to filter quickly.

  • Security log
  • T1078
Environment
Windows 10 / Server
Tools
eventvwr.msc, XML filters
Focus
Authentication & account events
ATT&CK
T1078 Valid Accounts, T1136 Create Account

Walkthrough

  1. Open the Security log

    Run eventvwr.msc → Windows Logs → Security. Reading it requires administrator rights.

  2. Filter to the events that matter

    Filter Current Log → Event IDs: 4624,4625,4634,4672,4720,4732,4740.

  3. Read a failed logon (4625) field by field

    The important fields are Account Name, Logon Type, Source Network Address, and the Status / Sub Status code, which tells you why the logon failed.

  4. Build a reusable custom view

    Create Custom View → XML → Edit query manually. This one shows only failed network logons:

    <QueryList>
  <Query Id="0" Path="Security">
    <Select Path="Security">
      *[System[(EventID=4625)]]
      and *[EventData[Data[@Name='LogonType']='3']]
    </Select>
  </Query>
</QueryList>
  5. Look for persistence after access

    An attacker who gets in often creates an account (4720) and adds it to Administrators (4732). Those two events close together are a high-priority finding.

  6. Export the evidence

    Save Filtered Log File As → .evtx to preserve the evidence, or CSV for a quick review.

Decoder: failure codes & logon types

4625 Sub StatusMeaning
0xC000006ACorrect username, wrong password
0xC0000064Username does not exist (often enumeration or spraying)
0xC0000234Account is locked out
0xC0000072Account is disabled
0xC000006FLogon outside allowed hours
Logon TypeMeaning
2Interactive (at the keyboard)
3Network (SMB, file shares, SSH on Windows)
5Service
7Unlock
10RemoteInteractive (RDP)

Key takeaways

  • A lot of 0xC0000064 (unknown user) failures suggests someone is guessing usernames, not just passwords.
  • Logon Type tells you the access path. Type 10 from an external IP deserves attention fast.
  • Knowing the raw event makes SIEM queries much easier to write and trust.
