ServiceNow Incident Handling

Security work runs on tickets. I worked a reported phishing email through ServiceNow's incident lifecycle, focusing on accurate prioritization and notes the next person can actually use.

Walkthrough

  1. Log the incident

    Caller, category (Security), affected configuration item, and a short description that says what happened, not what the user guessed.

  2. Set impact and urgency

    ServiceNow calculates priority from the two. A phishing email that one user clicked: Impact Medium (one user), Urgency High (credentials may be exposed) = P2.

  3. Assign to the right group

    Route to the security operations assignment group, not to a single person, so it's covered across shifts.

  4. Work notes vs. additional comments

    Work notes are internal: IOCs, actions taken, evidence. Additional comments go to the caller in plain language. Mixing them up leaks internal detail.

  5. Resolve and link knowledge

    Resolution code and notes, then a Knowledge Base article ("How to report a phishing email") linked so the next one is faster.

Key takeaways

  • Priority is a calculation, not a feeling. Impact × urgency keeps it consistent across a team.
  • A ticket is a record that someone else will read during an audit or a follow-up investigation.
  • Every repeat issue is a knowledge article waiting to be written.
