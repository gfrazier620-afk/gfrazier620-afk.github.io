PowerShell for Windows Triage

I used PowerShell to gather in a few minutes the evidence an analyst needs from a Windows host: what's running, who's been trying to log in, what's talking out, and what's set to start automatically.

Walkthrough

  1. Processes, with command lines

    Get-Process doesn't show command lines. CIM does, and that's where encoded or odd arguments show up.

    Get-CimInstance Win32_Process |
    Select-Object ProcessId, ParentProcessId, Name, CommandLine |
    Sort-Object Name
  2. Failed logons in the last 24 hours, grouped by source IP

    Get-WinEvent replaces the older Get-EventLog. Parsing the event XML pulls out the source IP field.

    Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625; StartTime=(Get-Date).AddDays(-1)} |
    ForEach-Object { ([xml]$_.ToXml()).Event.EventData.Data |
        Where-Object Name -eq 'IpAddress' } |
    Group-Object '#text' | Sort-Object Count -Descending
  3. Active network connections and their owners
    Get-NetTCPConnection -State Established |
    Select-Object LocalPort, RemoteAddress, RemotePort,
        @{n='Process';e={(Get-Process -Id $_.OwningProcess).Name}}
  4. Check common persistence locations
    Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Run'
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run'
Get-ScheduledTask | Where-Object State -eq 'Ready' |
    Select-Object TaskName, TaskPath
Get-LocalGroupMember Administrators
  5. Automate it into a triage script

    Wrapped the checks into a script that writes CSVs to a timestamped folder, so collection is consistent every time.

    $out = "C:\Triage\$(Get-Date -Format yyyyMMdd-HHmm)"
New-Item -ItemType Directory -Path $out | Out-Null
Get-CimInstance Win32_Process | Select-Object ProcessId, Name, CommandLine |
    Export-Csv "$out\processes.csv" -NoTypeInformation
Get-NetTCPConnection | Export-Csv "$out\connections.csv" -NoTypeInformation
Get-LocalGroupMember Administrators | Export-Csv "$out\admins.csv" -NoTypeInformation

Key takeaways

  • Parent-child process relationships matter: winword.exe spawning powershell.exe is a classic red flag.
  • Scripted collection is faster and repeatable, and it doesn't miss steps under pressure.
  • Run Keys and scheduled tasks are the first places to look for persistence.
