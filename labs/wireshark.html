Packet Analysis with Wireshark

Logs tell you what a system recorded. Packets show what actually crossed the wire. I used Wireshark to read normal traffic and pick out the patterns that should raise an analyst's eyebrows.

Walkthrough

  1. Capture vs. display filters

    Capture filters (BPF syntax, e.g. host 192.168.56.101) limit what's recorded. Display filters limit what's shown, and that's where most analysis happens.

  2. Find the TCP handshake

    Filter on SYNs, then follow the SYN → SYN/ACK → ACK sequence for one connection.

    tcp.flags.syn == 1 && tcp.flags.ack == 0
  3. Get the big picture first

    Statistics → Protocol Hierarchy and Statistics → Conversations show who talked to whom and how much, before digging into individual packets.

  4. Inspect DNS and HTTP

    Right-click → Follow → TCP Stream rebuilds the whole HTTP conversation.

    dns
dns.qry.name contains "example"
http.request
  5. Spot a port scan

    One source sending SYNs to many ports, and getting RSTs back, is a scan. The Conversations view makes it obvious.

    tcp.flags.syn == 1 && tcp.flags.ack == 0 && ip.src == 192.168.56.102
tcp.flags.reset == 1
  6. Catch cleartext credentials

    Legacy protocols send usernames and passwords in the clear. That's a finding in itself.

    ftp || telnet || http.authbasic

Filters I keep handy

FilterUse
ip.addr == x.x.x.xAll traffic to or from a host
tcp.port == 443Traffic on a specific port
dns.flags.rcode == 3NXDOMAIN responses (possible DGA malware)
http.request.method == "POST"Uploads and form submissions
tcp.analysis.retransmissionNetwork problems vs. security issues
!(arp || dns || icmp)Cut background noise

Key takeaways

  • Start with Statistics, then drill down. Scrolling packet by packet doesn't scale.
  • A wall of RSTs from one target is the clearest sign of a SYN scan.
  • Any cleartext credential in a capture is a finding worth reporting on its own.
