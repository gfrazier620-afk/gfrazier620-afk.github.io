Building an Isolated Security Home Lab

Every other lab here runs on this one. I built a virtual lab where attacks can be practiced safely: isolated from my home network, and easy to reset to a clean state.

  • VirtualBox
  • Kali
  • Networking
  • Snapshots
Environment
VirtualBox on Windows host
VMs
Kali, Windows 10/Server, Ubuntu, Metasploitable 2
Focus
Isolation, repeatability

Topology

 Host (Windows)
  |
  +-- NAT network ---------- internet for updates (toggled off during attacks)
  |
  +-- Host-only 192.168.56.0/24  (attack lab, no internet)
        |-- Kali Linux          192.168.56.102   attacker
        |-- Windows Server      192.168.56.110   target / log source
        |-- Ubuntu Server       192.168.56.120   target / Splunk forwarder
        |-- Metasploitable 2    192.168.56.101   intentionally vulnerable

Choosing network modes

ModeReaches internetReaches home LANUse
NATYesNoUpdates and downloads
BridgedYesYesAvoid for attack labs
Host-onlyNoNo (host only)Attack lab, the default here
InternalNoNoFully isolated VM-to-VM

Walkthrough

  1. Create VMs and attach to host-only

    Each VM gets an adapter on the host-only network, and a NAT adapter only when it needs updates.

  2. Verify isolation

    From Metasploitable, an internet ping should fail. A vulnerable box must never reach the outside.

    ping -c 2 8.8.8.8      # expect: Network is unreachable
  3. Snapshot a clean baseline
    VBoxManage snapshot "Win-Server" take "clean-baseline" --description "patched, logging on"
  4. Roll back after each exercise
    VBoxManage controlvm "Win-Server" poweroff
VBoxManage snapshot "Win-Server" restore "clean-baseline"

Key takeaways

  • Never bridge a vulnerable VM. It puts an exploitable machine on your real network.
  • Snapshots make labs repeatable and mistakes free.
  • A home lab is the best way to learn: break it, watch the logs, fix it.
